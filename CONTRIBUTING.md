# Contributing to arduino-playtime

Thank you for your interest in contributing! Here are a few guidelines to help things go smoothly.

## Reporting Issues

- Search [existing issues](../../issues) before opening a new one to avoid duplicates.
- Provide as much detail as possible: board model, IDE version, wiring/schematic if relevant, and steps to reproduce.

## Submitting Pull Requests

1. Fork the repository and create a feature branch from `main` (or the default branch).
2. Keep each PR focused on a single change or feature.
3. Include a clear description of **what** changed and **why**.
4. Ensure your sketch compiles cleanly in the Arduino IDE before submitting.

## Code Style

- Follow the existing indentation and formatting conventions in each sketch.
- Use descriptive variable and function names.
- Add brief comments for non-obvious logic.

## Testing Expectations

- Verify that your sketch compiles without errors or warnings.
- If you have the relevant hardware, test on the target board before submitting.
- Note any hardware requirements (sensors, libraries, wiring) in the sketch header or in the PR description.
